# Workforce census — where the checking happens

There used to be three files here — `census_2022_tables.md`,
`census_2023_tables.md`, `census_2024_tables.md` — regenerated by
`m06_workforce_census` on every run. Each paired a parsed value with the line
it came from, and each printed this at the top:

```sql
UPDATE workforce_census_metrics SET verified = 1 WHERE census_year = 2023;
```

**That statement now aborts.** Migration `0033` refuses `verified = 1` on any
census metric with no decision row behind it, on `UPDATE` and on `INSERT`.

The reason is not that the worklist was inaccurate. It is that one statement
set twenty flags, attributed them to nobody, and left no record that anybody
had read a page — so "who checked this figure, and against what?" had no
answer, which is the question the whole warehouse is built to be able to
answer. 68 metrics sat at `verified = 0` for as long as that was the only
route across, not for want of a decision about any one of them.

## The route now

The **Census tab** in the operator UI (`./start.sh web`, then `/admin`).

Each figure is shown with its own parsed line *and* with the full archived text
of the page that line sits on — `workforce_census_page_text`, which `m06` has
been storing since it was written and which nothing read until now. A figure
becomes verifiable once its page has been expanded in that session, the same
gate the Candidates tab puts on opening a document, and for the same reason:
the act being recorded is that somebody looked.

Deciding writes a `census_verifications` row carrying who, when, the value and
unit as they read at the time, and the URL and SHA-256 of the report those
bytes came from — `checked_against_*`, because nothing is fetched here. The
report was fetched, hashed and archived by `m06`; a verification is a
statement about those bytes, not a retrieval of its own.

Rejecting is bulk and also files a `parse_failures` row, so a bad parse is
findable from the parser's side rather than only from the figure's.

## Two things verification does not mean

**It does not mean comparable.** Provider participation varies between census
rounds and the reports say so in terms. Two verified years still must not be
differenced — see [`CAVEATS.md`](../CAVEATS.md). Verification raises the
confidence that a number was transcribed correctly and changes nothing else.

**It does not survive the source moving.** If a later parser revision reads a
different number off the same line, or the publisher reissues the PDF at the
same URL, the verification no longer vouches for what the row now says. The
Census tab lists those figures at the top as stale, with what changed; the
honest answer is to reset them and check them again.

## The page numbers

`source_page` is a **zero-based index** into the pages `pdfplumber` extracted,
which is what `m06` stored and what every figure and every archived page
carries. A PDF viewer counts from 1, so its page numbers are one higher. The
Census tab says so where it shows a page, and serves the archived text rather
than sending you to the PDF, so the offset only matters if you go and check in
a viewer as well — which is worth doing at least once per report.
