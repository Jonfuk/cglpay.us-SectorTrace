The API

Everything on this portal is drawn from a read-only JSON API on this same server. It is documented here so that the audience most likely to want the numbers — people working in a notebook, a spreadsheet or R — does not have to reverse-engineer it from the pages.

Read this with the figures. Every response carries the caveats that govern the numbers in it, in a caveat or caveats key. They are not boilerplate: they lead with the things that must not be computed from this data — no arithmetic across evidence layers, no differencing of workforce census years, no defensible total contract value. A figure quoted without its caveat is a figure this project cannot defend, and it will be disputed by whoever it is quoted at.

Choose a route by task

  • Browse the portal. Start with summary, providers, or authorities.
  • Compare or map places. Use compare, geography, and layers.
  • See who an authority or provider commissions. Use relationships.
  • Explore a subject. Go to contracts, pay, fingertips, or pfd.
  • Download complete data. Use the export route; page-facing responses may contain a window of rows, while exports carry the full filtered set and provenance.

How it behaves

  • Read-only. GET and HEAD only. There is no write route under /api/v1/ and a POST to one is a 404.
  • No authentication and no API key. The security model is the bind address: this server is meant to run on a machine or a network you trust. A per-address rate limit answers sustained abuse with 429 and Retry-After — generous enough that ordinary use never sees it — so please be no less polite than the pipeline is to its own sources regardless.
  • Same-origin. No CORS headers are ever sent, so a page on another site cannot read these responses from a browser. A script, a notebook or curl is unaffected.
  • Cached for five minutes. These answers change only when a pipeline module runs, which is hours apart at best.
  • Errors are JSON. A failure returns {"error": "…"} with a 4xx status and a message meant for a person.
  • Personal data is unreachable. Every query behind these routes declares the tables it reads and is refused if one of them holds personal data. That is enforced in code, not asserted in a policy.
  • Nothing is inferred. A value that could not be parsed is null with a logged reason, never a guess or a zero. Do not read null as "none".

The routes

/api/v1/summary

Headline counts across the corpus: providers, authorities, contract notices and their values, the latest workforce census metrics, and the pipeline's own collection state.

No parameters.

Returns providers, authorities, contracts (with value_is_concentrated, which is why this portal publishes no headline contract total), workforce, pipeline, funnel (the candidate-to-evidence verification funnel: discovered, undecided, promoted, rejected, evidence_rows).

/api/v1/summary

/api/v1/meta

Release identity for this deployment: the environment, the running revision and build_time, the database backend, the schema block (latest applied migration and count) and a capabilities block (admin UI, response cache, rate limit, document analysis, semantic search, and any PostgreSQL extensions installed). It lets a reviewer confirm which build and schema they are looking at. Per-source collection times are /api/v1/freshness; /health stays the plain liveness check.

No parameters.

/api/v1/meta

/api/v1/providers

One row per provider, with matched contract value, tribunal and CQC counts, latest charity income, and the register identifiers (company_number, charity_number) so a reader can verify at source.

No parameters.

Returns providers: an array.

/api/v1/providers

/api/v1/providers/{provider_key}/timeline

The deep dive on one provider: dated events from charity financials, tribunal decisions, NHS job adverts and contract awards, plus its CQC locations and the entity edges that link it to companies and charities. provider_key is the provider_key field from /api/v1/providers.

Returns provider, events, cqc_locations, entity_edges, tribunal_cases, charity_finance, cqc_inspections, disclosure (with gaps, disclosed and not_searched kept apart), filings, pfd_mentions, caveats.

/api/v1/providers/change_grow_live/timeline

/api/v1/providers/{provider_key}/lineage

The verified administrative record of an organisation's identity — renamed, merged into another body, or dissolved — from the pipeline's lifecycle config, cross-checked against the registered company and charity record. Not a statement about continuity of service, staff, contracts or quality: a merged charity's services and workforce may have moved, stayed or ended, and this does not say which. Evidence that names an older identity stays attached to that identity. No ownership structure is inferred and no individual officer is named.

Returns provider (provider_key, canonical_name, status, is_target), edges — each with relationship (renamed_to, merged_into, dissolved, renamed_from, merged_from), direction, the other provider_key / canonical_name and its basis — chain (this entity forward to the surviving one, with a cycle guard), identifiers (config-verified company / charity / CQC ids and their role) and caveat.

/api/v1/providers/with_you/lineage

/api/v1/authorities

Every commissioning authority: ons_code, name, type, region. The ONS code is the join key for the geography, contracts and NDTMS routes.

No parameters.

/api/v1/authorities

/api/v1/authorities/{ons_code}

Everything the warehouse holds about one authority: coverage ticks (W-12), grant allocation and budgeted spend as published, the budget lines behind the budget figure (W-27), treatment estimates with their paired confidence intervals, and the contracts it let. ons_code is the ons_code field from /api/v1/authorities.

Returns authority, coverage, grant, budget, budget_detail, treatment (fingertips and ndtms, with the same pairing rules the treatment page uses), contracts, caveats.

The grant and the budget are different figures from different documents and are never combined or divided — the payload keeps them separate and so must anything built on it. budget_detail carries amounts as published: no per-capita, no inflation adjustment, no ratio.

/api/v1/authorities/E08000025

/api/v1/compare

The existing series for two or more authorities or providers, drawn on shared axes — the campaign's "how does my authority compare?" answered in the only shape this pipeline may give it: the reader picks the peers. No new data: every series is the series an existing endpoint returns (grant and budget as the geography page draws them, treatment as the treatment page draws it, contracts by publication year as the contracts page counts them), composed for the chosen entities.

ParameterMeaning
ons_codeAn authority from /api/v1/authorities. Repeatable.
provider_keyA provider from /api/v1/providers. Repeatable.

Returns authorities, providers, series keyed by layer — grant, budget, treatment, contracts for authorities, charity and provider_contracts for providers — each carrying its own caveat, plus caveats.cross_layer.

The charts share axes with each other's authorities, never with each other's layers: nothing in the payload is combined, differenced or divided, and a gap between one chart and another is not a finding. At least one parameter is required; an unknown code is a 400.

/api/v1/compare?ons_code=E08000025&ons_code=E06000047&provider_key=change_grow_live

/api/v1/provider_compare

Two to four providers laid out across four separate pay-evidence layers: Living Wage accreditation, the latest gender pay gap filing, pay a provider published on its own website, and its ten most recent NHS Jobs adverts. The layers are placed side by side, never combined — the response has no ranking, score, difference or ratio, and a provider absent from a layer has not been shown to be worse or better on it. Non-temporal by design: this is not /api/v1/compare's time series.

ParameterMeaning
provider_keyRequired, repeatable. Between two and four distinct providers from /api/v1/providers; fewer or more is a 400, as is an unknown key.

Returns providers (key and name, in the order asked) and layers — living_wage, gender_pay_gap, provider_pay, nhs_jobs — each with its own unit, a by_provider map of rows keyed by provider, and its own caveat, plus a top-level caveat. There is no CSV form: unlike measures must not be flattened into one table.

/api/v1/provider_compare?provider_key=change_grow_live&provider_key=turning_point

/api/v1/relationships

One authority or provider's commissioning neighbourhood in the evidence graph — a one-hop view centred on whichever entity you ask for, not a map of the whole corpus. A line means a contract notice named this authority as buyer and this provider as supplier; it is not a measure of size, value, importance or reliance. Only deterministic relationships are returned — contract awards backed by an exact supplier-name match — never an unreviewed inference.

ParameterMeaning
ons_codeAn authority from /api/v1/authorities. Exactly one of ons_code or provider_key is required.
provider_keyA provider from /api/v1/providers.

Returns center (the entity you asked about), neighbours (the entities it has commissioning relationships with), edges (each with its evidence source, retrieval date and any date range the relationship was valid for), and caveat. An authority or provider that exists but has no matched relationships returns an empty neighbourhood, not an error — the coverage floor is the same one contracts and compare already document.

/api/v1/relationships?ons_code=E08000025

/api/v1/contract_diary

Procurement lifecycle records read as dated events rather than disconnected notice rows: a notice published, an award, a contract period starting, a contract period ending. Every date is transcribed from the notice. An “ends” event is the contract period as published — it is not a forecast of renewal, re-tender, or completion — and no milestone or performance event is shown because the warehouse does not collect them. Scope the diary by provider, buyer authority, or a single OCDS process.

ParameterMeaning
provider_keyContracts whose supplier name matched this key (via supplier_aliases).
buyer_ons_codeContracts bought by this authority.
ocidOne OCDS process.
yearKeep only events in this calendar year.

Returns events (each with date, kind, title, value_core, source_url), months (event counts, for a calendar overview), span, counts, note and caveat.

/api/v1/contract_diary?buyer_ons_code=E08000025

/api/v1/discrepancies

Where two or more public sources report a different value for the same verified entity and field — a provider's legal name across Companies House, the CQC register and a gender-pay-gap filing; a company number; a CQC location's rating from the syndication API versus the bulk export — both values are shown side by side with their source and retrieval date. Nothing is reconciled, ranked, or called an error. This is not cross-source arithmetic: it adds and averages nothing, it only lets the reader see both. A closed registry of comparable field pairs decides what is compared; a field whose sources agree is listed as agreeing.

ParameterMeaning
provider_keyA provider from /api/v1/providers. Exactly one of this or ons_code.
ons_codeAn authority from /api/v1/authorities.

Returns entity, discrepancies (each with label, observations [source, value, as_of, source_url] and distinct_values), agreed, checked, note and caveat. Only identity-level fields (name, number, rating) are compared in this version.

/api/v1/discrepancies?provider_key=change_grow_live

/api/v1/cooccurrence

Documents and records in which two or more selected tracked entities are named together — in one document element, one coroner's report, one tribunal case, or one procurement notice — with the exact passage or structured field for each. Name matching uses only the verified variants in supplier_aliases (the explicit review step), and every structured mention already carries a confirmed provider_key. Co-occurrence is location, not a relationship. Two names in one passage may be a list, a comparison, or unrelated; for a verified connection use the pathfinder.

ParameterMeaning
keyA provider/supplier key. Repeat the parameter 2–5 times.

Returns entities, results (each with record_type, title, text or matched, and a link), counts (by_record_type), note and caveat. Documents are searched over committee papers and community drug-partnership documents only.

/api/v1/cooccurrence?key=change_grow_live&key=turning_point

/api/v1/coverage_timeline

For one selected provider or authority, exactly which periods each source holds — so a reader sees a gap before opening a section. Nothing is gap-filled. Each source's periods list is the distinct periods the warehouse actually holds for that entity; a period missing from a list means the source did not publish it or this pipeline has not collected it — it is never a zero. The only synthesised value is the years axis, drawn for alignment. A source with an empty list is shown, not hidden: "this source holds nothing for this entity" is itself the answer.

ParameterMeaning
provider_keyA provider from /api/v1/providers. Exactly one of this or ons_code.
ons_codeAn authority from /api/v1/authorities.

Returns entity, span / years (the axis), sources (each with title, period_kind, periods, held, link), note and caveat.

/api/v1/coverage_timeline?provider_key=change_grow_live

/api/v1/relationship_path

A neighbourhood view answers what surrounds one entity; this answers how two known entities are connected. It returns the shortest verified path between them through the source-backed entity graph (v_entity_edges). An edge whose basis is an unconfirmed name match — the review gate not yet passed — is not followed, and the restricted shared-officer edges never reach this surface at all. The traversal is deterministic: among equally short paths the one first in (relationship, node id) order is returned. Every hop carries its own source URL and retrieval date.

ParameterMeaning
from_type / to_typeprovider, authority or supplier. Default provider / authority.
from_id / to_idThe two entity ids (provider_key or ONS code). Both required.
max_hops1–8, default 6.

Returns found, hops, path (one row per hop: from, relationship, basis, to, source_url, retrieved_at), nodes and a note. No path within max_hops returns found: false with a reason, not an error.

/api/v1/relationship_path?from_type=provider&from_id=cgl&to_type=authority&to_id=E09000007

/api/v1/relationships/{relationship_id}

One AWARDED_TO edge (a relationship_id from an edges entry above), resolved to the authority and provider it connects, plus a dated timeline of every contract notice behind every edge between that same pair. It is the source events behind one relationship — not a history of the working relationship, a measure of its value or reliance, or evidence of organisational continuity. Missing notice dates are left blank, never inferred.

ParameterMeaning
relationship_idRequired, in the path. A relationship_id from an /api/v1/relationships edges entry; anything that is not an AWARDED_TO edge is a 400.

Returns authority and provider (name and identifier each), timeline — one entry per edge with valid_from / valid_to, confidence, the source notice (id, title, value, buyer/supplier names, published date, source URL, and a constructed notice_web_url) or null where the notice is no longer held — edge_count, truncated (true when more than 500 notices exist for the pair) and caveat.

/api/v1/document_search

Full-text search over page-level text extracted from published committee papers and community drug partnership documents — the two document types currently parsed by the document-analysis pipeline (docs/document-analysis.md). Not a search of the whole warehouse: PFD reports, tribunal judgments and every structured warehouse table are reached through their own routes above, not this one, and a document type is added to this search only after a deliberate decision that its extracted text carries no restricted personal data.

ParameterMeaning
qRequired. The search term(s). Quotes, OR and -term are honoured.
source_systemOptional. One of the values in the facets.source_system block; anything else is rejected.
document_typeOptional. One of the values in the facets.document_type block.
year_from, year_toOptional. Bound the document's published year; an undated page is excluded when either is set.
since_retrieved_atOptional ISO timestamp. Only pages collected on or after it.
limitOptional, default 25, maximum 50.
offsetOptional. Pages the ranked list; the order is stable across requests.

Returns results — one row per matching page/element, each with document_id, document_element_id, document_type, source_system, title, title_basis (source_label, pdf_metadata, heading, filename or unknown — how title was derived; null until the backfill has run), source_title (the collecting module's raw label), page_number, the matched text, source_url, retrieved_at and published_at — plus total, facets (a value/count list per facet, sized to the query and any date scope), filters, query and caveat. Relevance order is a reading aid, not a measure of evidential weight. A result is a page that contains the term, not a finding.

/api/v1/document_search?q=recruitment&source_system=committee_paper_promotion

/api/v1/documents/{document_id}

The bounded passage around one element of a document from /api/v1/document_search — enough surrounding text to interpret a hit without republishing the document. Reads the active parsed version only, and the same allowlist as the search: a document_id whose source is not searchable is not readable here either.

ParameterMeaning
document_idRequired, in the path. The document_id from a search result.
element_idOptional. A document_element_id from a search result to centre the window on; omitted, the window is the head of the document.
contextOptional, default 3, maximum 3. Elements to include either side of the anchor.

Returns the document's title, title_basis, source_title, source_url, source_system, published_at, retrieved_at, the parser identity, and an ordered elements window — each with text, element_type, page_number and an is_anchor flag — plus has_more_before / has_more_after, element_count and caveat.

/api/v1/documents/document-…?element_id=…&context=3

/api/v1/catalogue

A registry of every dataset this portal collects: for each, its title, official publisher and source URL, evidence layer, geography, update cadence, licence, the public warehouse tables it writes, and the single limitation that matters most before quoting it. Row counts and last-retrieved dates are measured against the warehouse on each request, so a dataset showing zero rows has not been collected here rather than being empty at source.

No parameters.

Returns datasets — one row per collecting module, each with dataset_id, module, title, publisher, official_url, evidence_layer (+ evidence_layer_label), geography, cadence, licence, tables (name, rows, last_retrieved_at), row_count, last_retrieved_at and caveat — plus evidence_layers (the layer vocabulary), count and a shared caveat. Datasets in different evidence layers are never added together.

/api/v1/catalogue

/api/v1/catalogue/{dataset_id}

One catalogue entry, by its dataset_id, with the full licence licence_statement and any licence_caution alongside the same fields the list returns.

ParameterMeaning
dataset_idRequired, in the path. A dataset_id from the catalogue list; anything else is a 400.

/api/v1/catalogue/procurement-notices

/api/v1/changes

A derived chronology of what the warehouse recorded changing — there is no persisted change-event table and this endpoint adds no collection-time write path. Each event is one kind: release (a run of the module runner), refreshed (a source table's latest retrieval moved), reparsed (a document got a new active parsed version), superseded (a provider now trades as a successor) or verified (a human review decision). A collection change, a parser change and a human-review change are distinct kinds and their counts are never added. This shows what this warehouse recorded changing, not what a source published.

ParameterMeaning
kindrelease, refreshed, reparsed, superseded or verified.
sourceOne source label from the feed.
evidence_typeOne evidence type / dataset id.
sinceISO date; keeps dated events on or after it.
limitDefault 200, capped at 500.

Returns events, counts (by_kind — never a total), kinds, note, caveat, truncated.

/api/v1/changes

/api/v1/publication_calendar

Each source's release cadence, computed on the request. A publisher that has released nothing and a collection here that has not run are different conditions, and freshness alone cannot tell them apart. Every row carries two cadences that are never merged: the publisher's stated period (transcribed in the dataset registry, present only where the source commits to a calendar) and an observed interval — the median gap between the distinct dates this warehouse holds retrieval timestamps for, shown only with three or more such dates and always an estimate. next_expected is projected from whichever basis applies (stated preferred); status is overdue, due, current or unknown.

ParameterMeaning
todayISO date to evaluate against; defaults to the server's current date. For reproducible views.

Returns datasets (each with stated_cadence, stated_cadence_days, observed_interval_days, observed_sample, cadence_basis, last_publication, next_expected, status), counts (by_status and by_basis — never a total), as_of, note, caveat.

/api/v1/publication_calendar

/api/v1/record_diff

Compare two revisions of one record rather than treating the latest row as timeless. kind=ocds diffs two procurement notices field by field and labels each changed field: a source field is verbatim from the OCDS release, so a change there is an amendment the publisher made; a derived field is a match or normalisation this pipeline recomputed between collections, so a change there need not mean the underlying notice moved. The two change counts are reported apart and never added. kind=document diffs two parsed versions of one document — a metadata diff (parser, schema, config hash) plus an element-aligned, text-aware diff of the body; unchanged elements are omitted.

ParameterMeaning
kindocds (default) or document.
a, bThe two revision ids (notice_id or document_version_id).
ocidkind=ocds: diff this OCID's two most recent notices instead of passing a/b.
document_idkind=document: diff this document's two most recent versions.

Documents are gated by the same source allowlist as document search — a source not searchable there is not diffable here.

/api/v1/feed/changes.atom

The “what changed?” stream as a stable Atom 1.0 feed, for a feed reader or any external subscriber. It takes the same kind / source / since_retrieved_at filter as /api/v1/changes. The feed <id> and every entry <id> are host-independent tag URIs derived from the event's own content, so a subscription keeps working across releases and across the dev and production hosts.

ParameterMeaning
kindrelease, refreshed, reparsed, superseded or verified.
sourceOne source label from the feed.
sinceISO date; keeps dated events on or after it.

Returns application/atom+xml, not JSON. Up to 100 entries, newest first.

/api/v1/feed/changes.atom

/api/v1/layers

The geography map's overlay layers: contracts aggregated to one point per commissioning authority, CQC-regulated locations, latest treatment rates per authority, and coverage — how many evidence kinds the warehouse holds per authority. Each layer carries its own caveats, read from the same source the export layers use, so the portal and the downloads cannot drift apart.

Returns layers, each with label, features and caveats. PFD reports are deliberately absent: they have no geometry, and coroner areas must not be mapped as if they were authorities.

No parameters.

/api/v1/layers

/api/v1/atlas_layers

The closed registry of the evidence atlas's layers. Each entry names the endpoint that serves it, its legend, its unit, the GeoJSON property that keys a feature, the accessible-table columns and its caveat. Exactly one layer is shown at a time — the atlas performs no arithmetic between layers and produces no composite score.

Returns layers, note. Takes no parameters.

/api/v1/atlas_layers

/api/v1/contracts

Contract notices, with aggregates computed over the whole filtered corpus and a window of individual notices. The aggregates are complete; the notices array is not, and total says how many rows the filters actually match. For every row, use the export route below.

ParameterMeaning
provider_keyOnly notices whose supplier name matches a known alias of this provider.
buyer_ons_codeOnly notices let by this authority.
year_from, year_toPublication year bounds, inclusive.
psr_only1 for notices let under the Provider Selection Regime only.
limitRows in the notices window. Default 500, maximum 5,000. Ignored by the export, which reads every row.

Returns total, total_value_gbp, value_concentration, matched_to_provider, date_range, by_year, by_provider, by_procedure_type, by_quarter, value_bands (in fixed bands that never move with the filters), ending_soon (notices whose published end date falls within two years, with the caveat saying what that does and does not mean), top_buyers, notices, caveats.

Each notice carries three link fields and they are three different claims: source_url is the API page the bytes came from — a paginated cursor, which is provenance and not a destination; notice_web_url is the address the release itself published, or null; notice_link is the one to put in front of a reader, with notice_link_basis saying whether it was published or constructed.

/api/v1/contracts?psr_only=1&year_from=2025

/api/v1/contracts/process/{ocid}

The notices that share one OCDS release id (ocid), grouped into the lifecycle stages the notices' own OCDS tags name — planning, tender, award, contract, amendment, termination, implementation. A stage with no notice is drawn as absent, never as an inferred completion: this view computes no completion, renewal, KPI achievement, supplier performance or organisational continuity.

ParameterMeaning
ocidRequired, in the path. The ocid of any notice in the process.

Returns ocid, buyer, stage_order, stages (each with stage, present and its ordered notices — id, OCDS tags, title, dates, value, suppliers, source URL and constructed notice_web_url), notice_count, date_range and caveat.

/api/v1/pay

The pay evidence, and the most caveat-heavy payload here: indicative wage per employee from charity accounts, NHS job adverts by band, repeatedly advertised roles, and the workforce census metrics with their verification flags.

ParameterMeaning
provider_keyOne provider's series only.
year_from, year_toFinancial year bounds, inclusive.

Returns charity_wage_series, nhs_job_adverts, nhs_job_by_band, repeat_advertised_roles, workforce_census, census_verified_count, census_total, statutory_pay_rates, living_wage_accreditations, gender_pay_gap_reports, provider_published_pay, ons_ashe_observations, skills_for_care_estimates, caveats.

The wage figure is wages and salaries divided by an average employee count. It is not a pay scale, a median salary or anyone's earnings, and the caveat saying so travels in the payload.

/api/v1/geography

One value per authority for a chosen metric — the choropleth's data, without the geometry. Geometry is 14 MB and does not change between metrics, so it is fetched once from /api/v1/boundaries and joined on ons_code.

ParameterMeaning
metricOne of grant_total (the default), grant_drug_alcohol, grant_per_head, budget_public_health, treatment_numbers, contract_value.

Returns metric, metric_label, year, unit, allocation_status, features, authority_mean, min, max, available_years, caveat.

authority_mean is the mean across authorities and is labelled as such. It is not "the England figure", which is a different number published separately. A grant allocation and a budgeted spend are different figures from different documents: do not substitute one for the other, and do not compute a ratio between them.

Authority boundary geometry as a GeoJSON FeatureCollection, keyed by ons_code. Large, and cached: fetch it once.

/api/v1/treatment_metrics

A catalogue of treatment metrics to read before a chart: one row per Fingertips indicator and per NDTMS source table, each with its definition, unit, whether a 95% confidence interval is published, the exact periods held (never gap-filled), authority and England coverage, and provenance. Computed from the same tables the treatment page charts.

Returns metrics, count, caveat. Takes no parameters.

/api/v1/treatment_metrics

/api/v1/ndtms

Local-authority NDTMS figures. Called without an authority it returns the catalogue — which sheets exist, how many authorities and publications each covers — rather than 17,231 rows.

ParameterMeaning
ons_codeOne authority's rows. Without it, only the catalogue is returned.
table_refOne published sheet.

Returns datasets, authority, estimates, other_rows.

These are modelled estimates published with 95% confidence intervals, and the interval is part of the figure. An estimate in estimates carries lower, upper and has_interval; where the publication printed bounds that cannot be attached to one estimate unambiguously, they are left unattached and has_interval is false. A confidence interval on the wrong estimate is invented, which is worse than an absent one. other_rows holds the rows with no number in them — suppression markers kept verbatim. A marker is not a zero.

/api/v1/ndtms

/api/v1/pfd

Coroners' Prevention of Future Deaths reports: reports by year (with the metadata stubs counted on the chart, not in a footnote), by coroner area, the concern-term finding aid, and the two mention facts kept apart — being sent a report and being named in one are different mention_types and are never summed.

No parameters.

Returns totals, by_year, by_coroner_area, concern_terms, mentions (sent_to_providers, naming_providers, recipient_organisations), recent, caveats. The names of the deceased are in restricted tables this route cannot read, and no restricted table is listed anywhere in the payload.

/api/v1/pfd

/api/v1/safety

Enforcement notices the Health and Safety Executive served on an organisation whose name exactly matches a tracked provider. A notice is a point-in-time fact, not a settled outcome: the register's own result — which can be Under appeal, Withdrawn or an appeal decision — travels with every notice, and nothing here infers compliance. Notices served on individuals are excluded at collection, and the register covers only HSE-enforced workplaces, so an absence of notices is not a safety rating.

No parameters.

Returns notices (each with notice_number, recipient_name, provider_key, notice_type, issue_date, compliance_date, result, legislation, contravention_text and the source URL), by_provider, by_type, total and caveat.

/api/v1/safety_legal

One filterable chronology over five distinct accountability sources — Prevention of Future Deaths reports, Safeguarding Adult Reviews, HSE enforcement notices, employment-tribunal cases and CQC inspections. Each event carries exactly one relationship label: addressed_to (the document was sent to the organisation), named_in (the organisation is mentioned — not a finding), matched_to (an exact name match in a register) or regulated_by (a registration/inspection record). The four are never summed and a mention is never a finding of fault.

ParameterMeaning
sourcepfd, sar, hse, tribunal or cqc.
relationshipaddressed_to, named_in, matched_to or regulated_by.
provider_keyOne tracked provider.
year_from, year_toBound the dated events.

Returns events, counts (by_source, by_relationship — never a total), labels, sources, caveats (one per source), note, truncated.

/api/v1/cqc_locations

CQC-registered locations belonging to a provider this pipeline tracks. CQC registration covers only certain regulated activities — residential detox, inpatient care, some prescribing — so most community drug and alcohol provision is not registered: this is a map of regulated locations, never a complete service map, and a count of locations is neither coverage nor quality. Do not rank authorities or providers by it, and do not combine it with any other layer. No personal data: CQC's registered-manager names are held in a restricted table and never reach this route.

ParameterMeaning
provider_keyOptional. One tracked provider.
authority_ons_codeOptional. Resolved local authority of the location.
registration_statusOptional. One of the facets.registration_status values.
regulated_activityOptional. Contains match against the comma-joined activities (CQC's activity names contain commas, so the column cannot be split exactly).
service_typeOptional. An exact gacServiceType name; one of the facets.service_type values.
ratingOptional. Overall rating, matching the API rating or the bulk-export fallback.
limitOptional, default 100, maximum 500.
offsetOptional. Pages the list; the order is stable.

Returns results — one row per location with location_id, provider_key, provider_name, location_name, postal_code, latitude, longitude, local_authority_raw, local_authority_ons_code, region, registration_status, overall_rating, overall_rating_date, rating_source (api or bulk_export), regulated_activities, service_types and the source URL — plus total, without_coordinate (rows in the current filter that cannot be placed on a map), facets (a value/count list for registration_status, overall_rating, region and service_type), filters and caveat.

/api/v1/claims

The campaign's claims, each linked to the evidence that supports it and approved by a named reviewer. Nothing in this response is computed: the claim text is what a person wrote, the citations are rows a person picked, and the caveats are lines a person wrote about what may not be computed from it.

No parameters.

Returns claims: an array of id, claim_text, caveats (one line each), citations (each with a resolved object of label, url, source_url and retrieved_at — or null when the row it named is no longer in the warehouse), published_by, published_at and note. Only published claims are served; a claim is published only by a recorded decision.

/api/v1/freshness

When each source table was last written by a pipeline run — the newest retrieved_at per table. Served on its own route rather than inside /api/v1/summary because it is seconds of full table scans; the overview loads it lazily after first paint.

No parameters.

Returns tables: an array of label, table and retrieved_at (or no date at all — never collected is "never", not a zero), plus caveat.

/api/v1/export

The same figures as a file, with the provenance written into it. A CSV gets separated from any accompanying note within about a day of leaving this server, so the endpoint it came from, the filters that produced it, the number of rows it holds and the licence terms are all comment lines at the top of the file — and the same object is in the X-Provenance response header.

ParameterMeaning
endpointOne of summary, providers, authorities, contracts, pay, geography, fingertips, ndtms.
formatcsv (the default) or json.
any filterEvery parameter the underlying route accepts is forwarded, and is recorded in the file's filters_applied line.

An export is complete for its filters. It is not the page's window: a contracts export reads every notice the filters match, streamed, however many that is, and the # rows: line says how many so the file can be checked against itself. A limit in the query is ignored here.

/api/v1/export?endpoint=contracts&format=csv&psr_only=1

/api/openapi.json

Provenance, in every row

Most rows carry source_url, retrieved_at and payload_sha256: the document the value came from, when it was fetched, and the SHA-256 of the exact bytes, which are archived. That is what makes a figure from here checkable by someone who does not trust it — which is the only kind of checking that matters.

Licence terms are per source and not uniform. Most of this material is under the Open Government Licence v3.0, which requires attribution; the workforce census is NHS Benchmarking Network content with its own terms, and council documents vary by council. Every CSV export names the licences its rows can be under, in # licence: lines.

The portal renders these same responses as charts and tables, each with the caveat that governs it pinned beside it.

Read the caveats before quoting anything. They lead with the things that must not be computed from this data.
